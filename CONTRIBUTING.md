# Contributing to VizMLIR

Thanks for taking the time to improve VizMLIR. Small, focused changes are welcome, especially improvements to MLIR parsing, graph rendering, and the browser workflow.

## Before you start

1. Install Node.js 20 or newer, Rust, Cargo, and the `wasm32-unknown-unknown` Rust target.
2. Install dependencies with `npm ci`.
3. Start the app with `npm run dev` and open the local URL printed by Vite.

## Project layout

- `src/main.js` wires the browser UI and application state.
- `src/wasm/` is the JavaScript bridge and views for the Rust module.
- `src/render/` contains graph rendering code.
- `wasm/src/` contains the MLIR lexer, parser, arena, and exported ABI.
- `public/mlir_core.wasm` is generated by the WASM build and should not be edited by hand.

## Making changes

- Keep changes focused and preserve the existing browser-only architecture.
- When changing `wasm/src/abi.rs`, update the matching declarations in `src/wasm/abi.js`.
- When changing parser output, check both valid input and malformed MLIR in the app.
- Do not commit build output from `dist/`, `wasm/target/`, or generated WASM unless a release process specifically requires it.

## Checks

Run the full production build before opening a pull request:

```bash
npm run build
```

For Rust-only changes, these checks are also useful:

```bash
cargo fmt --manifest-path wasm/Cargo.toml -- --check
cargo check --manifest-path wasm/Cargo.toml --target wasm32-unknown-unknown
```

In a pull request, describe what changed, how you tested it, and include a small MLIR example when the behavior is parser- or rendering-related.
